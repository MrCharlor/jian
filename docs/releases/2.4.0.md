### Features

* **decisions:** the Jev client asks several typed questions (yes or no, choice, score) over one state in a single request; every use below is general, for any profile and any kind of work, and falls back to the previous behaviour when there is no key, the key is refused, or Jev is slow or down ([0c0da44](https://github.com/lucasaarch/jian/commit/0c0da44c6281a51234d90a6fe1943fb814cc25b0))
* **decisions:** the action guard asks one question per risk (destroys, hard to undo, exposes) and whether the request asked for exactly this action, and says which risk weighed when it stops one; it covers commands and file changes, any MCP tool its server does not declare read-only, and what is sent to people, conversations or agents ([0c0da44](https://github.com/lucasaarch/jian/commit/0c0da44c6281a51234d90a6fe1943fb814cc25b0))
* **decisions:** outside content (fetched pages, searches, MCP results) that addresses the agent with instructions arrives with a warning; nothing is removed ([0c0da44](https://github.com/lucasaarch/jian/commit/0c0da44c6281a51234d90a6fe1943fb814cc25b0))
* **decisions:** before a turn, Jev leaves out recalled memories that do not bear on it, names the skill that fits, and marks a plainly light turn, which then runs at low reasoning effort, never above the owner's choice and never switched off ([0c0da44](https://github.com/lucasaarch/jian/commit/0c0da44c6281a51234d90a6fe1943fb814cc25b0))
* **memory:** a new memory about a subject already kept is held once and the agent is shown the existing key and version to update; saving again under the same key saves it ([0c0da44](https://github.com/lucasaarch/jian/commit/0c0da44c6281a51234d90a6fe1943fb814cc25b0))
* **decisions:** the learning look-back is skipped when the work plainly holds nothing to keep, and in a group with several agents the mention check knows the other agents ([0c0da44](https://github.com/lucasaarch/jian/commit/0c0da44c6281a51234d90a6fe1943fb814cc25b0))
* **decisions:** the tokens Jev spends are counted per UTC day and use, counts only; Providers › Decisions in the panel shows today's and the last seven days', with a switch for each use and an optional daily ceiling past which the fixed rules decide until 00:00 UTC (`GET` and `PATCH /v1/decisions`) ([6654367](https://github.com/lucasaarch/jian/commit/6654367fc1b82d707dd1e10189d2ef59ae4d42c8))
* **decisions:** the same questions over the same state within 10 minutes are answered from a cache and not paid, and the action guard sends the request only when the action alone shows a risk, with the same outcome as asking everything at once ([6654367](https://github.com/lucasaarch/jian/commit/6654367fc1b82d707dd1e10189d2ef59ae4d42c8))

### Upgrading

Migration `0039_decision-usage` runs on start and adds the `decision_usage` table; nothing else changes. Without a TypeSafe key the gateway behaves as in 2.3.0. With one, every use starts switched on and there is no daily ceiling; set them in Providers › Decisions. With several gateway processes, the ceiling may be passed by what the others spent in the last 30 seconds.
